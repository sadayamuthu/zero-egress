## Notes and findings

1. **Debian package added a Microsoft apt repository (fixed in `b3f5d43`, ships next release).**
   The 0.1.0 `.deb` writes `/etc/apt/sources.list.d/vscode.list` pointing at `packages.microsoft.com`,
   so every later `apt update` contacts Microsoft. Where gpg exists, it also installs Microsoft's
   signing key. Where gpg is missing, the install fails. Its postrm deletes `vscode.list` and
   `microsoft.gpg` on removal, even if a real VS Code install owns them. Users who installed the
   0.1.0 `.deb` should check those two files and remove them unless they use VS Code's apt
   repository. Worth a line in the release notes.
2. **Debian package metadata is still upstream's.** `Maintainer: Microsoft Corporation`,
   `Homepage: code.visualstudio.com`, a VS Code description, and `Version: 1.99.3-<timestamp>`
   instead of 0.1.0. The rpm spec has the same Vendor and Packager. This was not changed here,
   because it needs an owner choice of maintainer identity.
3. **Terminal tool timeout message.** The command ran and its output came back, but the tool
   result said it was "automatically killed by ZeroEgress after 8s of inactivity and did not finish
   successfully". This is probably upstream prompt-detection behaviour with a throwaway HOME
   (no zsh shell integration). Cosmetic, but misleading.
4. **Harness notes, not product bugs.** (a) With a fresh HOME that has no login keychain, the
   macOS app blocks before its first window (keychain prompt); `--use-mock-keychain` avoids it.
   (b) Docker's amd64 emulation refuses to exec AppImages ("Exec format error") because of the
   AppImage magic bytes in the ELF header; zeroing bytes 8–10 of a copy works around it.
   (c) The Linux `bin/zero-egress` launcher detaches, so under `xvfb-run` the launch check calls
   `/usr/share/zero-egress/zero-egress` directly.
5. The packaged app writes `~/Library/Application Support/Microsoft/DeveloperTools/deviceid`
   (upstream `@vscode/deviceid`). This is local only, with no egress observed, but it is a
   persistent machine identifier; consider removing it in a later release.
