# Advisory: the v0.1.0 `.deb` registers Microsoft's apt repository

Affects: `zero-egress_0.1.0_amd64.deb` only. The `.rpm`, AppImage, `.tar.gz`,
macOS and Windows builds of 0.1.0 are not affected. The fix is on `main`
(commit `b3f5d43`) and ships in the next release.

## What happened

The 0.1.0 `.deb` still carried upstream VS Code's package scripts.

- **On install** (`postinst`), when `gpg` was present and the files did not
  exist yet, it wrote:
  - `/etc/apt/sources.list.d/vscode.list`, pointing apt at
    `https://packages.microsoft.com/repos/code`;
  - `/etc/apt/trusted.gpg.d/microsoft.gpg`, Microsoft's package signing key.

  From then on every `apt update` on that machine contacts
  `packages.microsoft.com`, and apt trusts packages signed by that key. Neither
  is something ZeroEgress should ever do.
- **Without `gpg`** (for example a minimal Ubuntu 24.04 image), the install
  failed: dpkg exited 127, apt exited 100, and the package was left
  half-configured (`dpkg -s zero-egress` shows `install ok half-configured`).
- **On removal or upgrade** (`postrm`), it deletes `vscode.list` and
  `microsoft.gpg` every time it runs, including during the upgrade from 0.1.0
  to a later version. If you also use Visual Studio Code from Microsoft's
  repository, that removes VS Code's own apt source and key.
- It also stored a debconf answer, `zero-egress/add-microsoft-repo`.

The paths above are the Debian/Ubuntu defaults. The script asked apt for them
(`Dir::Etc::sourceparts` and `Dir::Etc::trustedparts`), so a system with a
custom apt configuration may have them elsewhere; `apt-config dump | grep -E
'sourceparts|trustedparts'` shows where.

## Check your machine

```sh
ls -l /etc/apt/sources.list.d/vscode.list /etc/apt/sources.list.d/vscode.sources \
      /etc/apt/trusted.gpg.d/microsoft.gpg 2>/dev/null
grep -rl packages.microsoft.com /etc/apt/sources.list /etc/apt/sources.list.d/ 2>/dev/null
dpkg -s zero-egress 2>/dev/null | grep -E '^(Status|Version):'
```

## Clean up

**If you do not use Visual Studio Code from Microsoft's repository**, remove
the repository and key, then refresh apt:

```sh
sudo rm -f /etc/apt/sources.list.d/vscode.list /etc/apt/trusted.gpg.d/microsoft.gpg
sudo apt update
```

**If you do use VS Code from Microsoft's repository, leave both files.** They
are VS Code's, and VS Code needs them for its updates. Note that upgrading or
removing ZeroEgress 0.1.0 runs the 0.1.0 `postrm`, which deletes them; after
that, re-create them with VS Code's own instructions
(<https://code.visualstudio.com/docs/setup/linux>), or back them up first:

```sh
sudo cp -a /etc/apt/sources.list.d/vscode.list /etc/apt/trusted.gpg.d/microsoft.gpg /root/
# ...upgrade or remove zero-egress...
sudo cp -a /root/vscode.list /etc/apt/sources.list.d/
sudo cp -a /root/microsoft.gpg /etc/apt/trusted.gpg.d/
```

**If the install was left half-configured** (no `gpg`), remove the package and
use the AppImage or the `.tar.gz` from the same release until a fixed `.deb`
is published:

```sh
sudo dpkg --remove zero-egress
```

**The debconf answer** is removed with the package's purge, or by hand:

```sh
echo PURGE | sudo debconf-communicate zero-egress
```
